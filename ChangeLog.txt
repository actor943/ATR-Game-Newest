0.4.9-修复（安卓端起名保存不生效）:
	修复：安卓端「我的」里改名保存后不生效，退出重启也不生效
		原因：profile.json / settings.json 的落盘目录在安卓上走 ``~/.config``
			（旧 _config_dir 把安卓 Linux 内核当成普通 Linux），该路径在安卓
			App 沙箱里不可写，save() 静默返回 None，名字从未真正落盘。
		处理：检测到安卓（ANDROID_DATA / build.prop / uname 含 android）时，
			改用 flet 通过 FLET_APP_STORAGE_DATA 暴露的 App 私有持久数据目录
			（可写且跨启动保留）；桌面端路径不变，不影响已有桌面存档。
			history.py 的 data_dir 同病，一并修正（比赛记录落盘同理）。

0.4.10-修复（音频打包 / 桌球联机返回 / 手机操控 / 现实参数 / 宽屏 UI / 白屏）:

修复：桌球等子菜单「界面完全空白」（白屏）
	根因：上一轮把 menu_card 默认设为 expand=True，但它被放在各游戏子菜单的
		Row(wrap=True)（Flutter 的 Wrap 控件）里。Flutter 规定 Expanded 只能
		存在于 Flex（Row/Column），放进 Wrap 会直接抛断言、整页白屏。
	处理：
		· menu_card 改回显式宽度（不再 expand）；
		· 各子菜单首页（桌球 / 五子棋 / 国际象棋 / 俄罗斯方块 / 掼蛋）改用
		  core.ui_common.grid_cards() 按页面宽度给每张卡算显式宽度来铺满，
		  彻底避开「Expanded 放进 Wrap」这个致命组合；
		· grid_cards 内部只用普通 Row（不带 wrap），卡片用显式 width，安全且填满。



修复：手机端不会打包音频文件
	原因：pyproject.toml 的 exclude 写死排除了 "assets/Songs"（首字母大写），
		在大小写不敏感的 macOS 上正好匹配到真实的 assets/songs，于是
		flet build apk 在 Mac 上打包时把整个音频目录都排除了。
	处理：移除该排除项，歌曲 / 音效随所有平台安装包一起打包；
		桌面端语音仍由 [tool.flet.<平台>].dependencies 的 sounddevice 提供
		（Android/iOS 无 PortAudio 原生 wheel，实时语音暂以优雅降级处理）。

修复：手机端 & Mac 端，多人桌球点「返回」直接退出房间、回到单人桌球
	原因：台球对局页的返回按钮写死跳 /g/billiards（单人子菜单），
		联机时应该回房间大厅而不是单人页。
	处理：返回时若处于联机（self.net 非空）则跳 /room（房间大厅），
		本地双人仍回 /g/billiards。

优化：手机端桌球「戳不准白球」
	原来必须按在半径 2.4 倍的母球上才能拉弓，白球只有二十几像素，手指
	触控面积大经常抓空。现在放宽：轮到你且母球在台面上时，在桌面**任意
	位置**按下都能拉弓（方向仍是「母球 − 指针」，手感不变）。

优化：桌球操控（现实世界参数 + 角度转盘 + 力度条）
	物理内核加入现实世界标准参数（球质量 0.17kg、9 尺桌 2.54×1.27m、
		反弹系数 0.95），并把「牛顿」作为力度输入单位：力度条 0~75 牛封顶，
		用冲量公式 F·Δt = m·Δv 归一化成 0~1 的 power（与联机协议一致）。
	新增外接控制器（games/billiards/views_controls.py）：
		· 角度转盘（轮盘）：手指在圆盘上指哪，击球方向朝哪；
		· 力度条（竖直）：从下往上拖，0 → 75 牛，实时读数；
		· 击球按钮：按当前角度 + 力度出杆。
	这两个控件摆在对局页下方的空位（桌面 / 手机都能用），原有「拖白球拉弓」
		手势保留，两套互不冲突；转盘还会把瞄准线实时画到球桌上。

优化：整体 UI 生成逻辑，铺满屏幕宽度（不再浪费右侧空白）
	新增 core/ui_common.grid_cards()：按页面宽度算列数，把卡片等宽铺到
		左右边缘；窄屏自动退化成单列。
	· 主菜单三扇门、单人游戏页所有游戏卡改用 grid_cards；
	· menu_card 默认改为 expand=True（原来写死 260px），所有游戏子菜单
		的卡片在宽屏上自动平分、铺满整行。

Bug（多人实测，掼蛋）：**房主出牌，客人的牌桌纹丝不动**；
	双方退出一局再回房间后，**房主第二次点开始，访客再也收不到

		**只有「客人」这一路会把动作告诉房主**，房主自己的
		出牌 / 过牌 / 进贡从来不广播 —— 客人的牌桌就一直停在

		推给所有人（出牌 / 过牌 / 进贡三处都补上）；客人的过牌
		补发 {"k":"pass"}
	根因二（房间变僵尸）：core/views/room_view.py 的房间轮询
		在跳进对局页时 `return` 结束；玩家从对局页退回房间时，

		还会稍后冒出来，变成房间里迟到的「房主发起了游戏」

		_POLL_OWNER，一个房间同一时刻只允许一个轮询在跑
		（房间视图会被缓存复用，新旧实例抢同一个事件队列，
		「开始」被旧实例吃掉就没人响应）；界面刷新只在房间页
		可见时做（对局页盖住时不去重绘整页）
	根因三（重传重复跳页）：可靠消息（need_ack）没收到 ACK 会
		重传，同一条「开始」可能被处理多次，把客人正在看的那
		张牌桌顶掉
	修：core/net/session.py 按 mid_seq 去重，同一条可靠消息
		只处理一次
	顺带（手牌归属）：掼蛋排座改以**席位表里我自己那条**为准

	验证：同一进程开两个线程当两台设备（各自的会话 / 路由器 /
		事件循环，真实 UDP 会话 + 真实 Router 全链路）：

Bug（多人实测）：房主点「开始」后，**客人不进入对局**，停在房间页
	根因：flet 1.0 的 page.run_task() 只收**协程函数**，传协程对象直接
		TypeError("handler must be a coroutine function")。而客人专属
		分支写的是 run_task(self._sync_wait())——带了括号，传的是协程
		对象：异常从对局页 build() 一路冒回房间页轮询协程，轮询静默死亡，

	为保证 spans 渲染稳定，引入新常量 TERMINAL_HEIGHT = 520，
		main_row 固定高度 + STRETCH，终端不再随行数长高，
		溢出由内部 Column 滚动；动画全部关掉

	炸弹比较：先比张数再比点数；同花顺同理
	parse 采用「就高解释」：同一组牌多窗口匹配时取最高（修复带野牌顺子的解释歧义）
	iter_combos：从手牌枚举全部可出牌型（出牌/跟牌候选生成），占用偏移选牌杜绝重复

	ai.py：贪心 AI（少烧逢人配、先甩低牌、不压搭档）
	simulator.py：headless 自对弈入口（python -m games.guandan.simulator），逐局校验牌数守恒与游序完整
	selftest.py：规则单元用例 + 引擎守卫 + 自对弈不变量（python -m games.guandan.selftest）
	实测：12+30 场自对弈全部正常收尾，两队胜率均衡（6:6），平均每场 9.8 局
	暂未实现：进贡/还贡/抗贡；「打 A 必须双下」竞赛变体（当前采用 A 级头游即胜）
